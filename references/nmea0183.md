# NMEA 0183: serial boundary and sentence handling

## Establish the port before interpreting bytes

NMEA describes 0183 as one talker feeding multiple listeners, normally at 4800
baud; its HS appendix specifies 38,400 baud. Do not join two talker outputs.
Use separate inputs and a multiplexer when combining sources. The actual
instrument manual determines speed, electrical interface and supported sentences.
[NMEA overview](https://www.nmea.org/nmea-0183.html).

Modern differential ports, legacy single-ended ports, RS-232 adapters and bare
3.3 V UARTs are different electrical interfaces. Prefer an isolated marine serial
interface with documented input/output behavior. Trace talker output to listener
input; do not infer direction or polarity from wire color alone. A/B labeling can
vary by manufacturer. Never connect a differential negative output to ground just
because an old single-ended diagram does so. Check the specific port manual.
[Actisense wiring guide](https://actisense.com/wp-content/uploads/2021/01/Everything-you-need-to-know-about-NMEA-0183-1.pdf).

Create a port record: terminal label, direction, differential/single-ended,
reference/shield handling, baud, framing (typically 8N1), isolation boundary,
receiver load and protection. Review its electrical limits against the component and adapter datasheets.
For an MCU, place a suitable line interface between the connector and UART.
For USB, test whether USB power, shielding or a laptop charger defeats isolation.
Do not apply the N2K two-terminator rule to an 0183 serial link.

## Parse as a stream, then interpret

The common sentence form is `$ttfff,field,...*HH\r\n`; encapsulated traffic such
as AIS commonly begins `!`. XOR the bytes after the opening delimiter and before
`*`; compare the two hexadecimal checksum characters. Preserve empty comma fields.
The conventional sentence limit is 82 characters including delimiters and CRLF;
real receivers may emit extended forms. Treat extensions as a named profile,
not an excuse to accept unbounded input. GPSD documents this ecosystem, but its
community reference is not the licensed NMEA standard.
[GPSD NMEA reference](https://gpsd.gitlab.io/gpsd/NMEA.html).

Recommended parser design:

1. Accumulate bounded bytes across reads; a serial read is not a sentence boundary.
2. Recover at a new start delimiter after overflow or corruption. Record rejected
   bytes and reason without allowing a large input to exhaust memory.
3. Verify framing/checksum before interpretation. Retain raw bytes alongside the
   decoded value and receive time. A checksum detects some corruption, not fraud.
4. Select a sentence/version parser and validate field counts, enumerations,
   numeric ranges and status. A syntactically valid sentence can contain no fix.
5. Emit a typed observation with source, units, validity and freshness. Preserve
   unknown/proprietary sentences as opaque records instead of guessing layouts.

The bundled inspector is intentionally narrower: one printable ASCII sentence,
mandatory checksum, standard 82-byte envelope, no tag block. CLI arguments may
omit CRLF; files may use LF or CRLF because log exporters normalize line endings.
This tolerance is for offline logs and is not wire-format validation. `$P...`
records are identified as proprietary without decoding fields. NMEA tag blocks,
checksum-less legacy records and vendor-long sentences are rejected explicitly.
Use a separately tested profile if the target requires them; never silently strip
metadata and call the result a complete validation.

## Semantic traps and bridge decisions

| Observation | Required interpretation |
|---|---|
| RMC/GGA/GLL position | Decode degrees/minutes, hemisphere and validity; do not treat `4916.45` as decimal degrees |
| RMC speed/course | Ground-relative motion; course can be unstable at low speed and is not heading |
| HDG/HDM/HDT | Preserve magnetic/true reference and variation/deviation meaning |
| DPT/DBT | Preserve depth reference and offset; avoid applying keel/transducer correction twice |
| MWV | Preserve relative/true reference, unit code and valid-data flag |
| AIS VDM/VDO | Preserve received-target vs own-vessel meaning and multipart assembly context |

A coordinate conversion example: `4916.45,N` becomes
`49 + 16.45/60 = 49.2741667°`; west longitude is negative. Reject minutes outside
[0,60), and validate final latitude/longitude ranges. Empty fields mean unavailable,
not zero. Keep time-only values distinct from a complete UTC date-time; log receipt
time is not proof of measurement time. Test midnight rollover and stale repeated
positions before downstream navigation use.

For AIS, a sentence checksum covers only that fragment. Assemble with bounded
lifetime and a key including input/source, channel and sequence information. Blank
sequence IDs and interleaving need an explicit ambiguity policy; do not splice
fragments from different receivers. Validate fragment count/index and final fill
bits, then hand the payload to a maintained AIS decoder. Never infer an AIS RF
transmit capability from the ability to generate a VDM sentence.

## Capacity calculation (design example, not standard limit)

For 8N1, budget 10 serial bits per ASCII byte. Six 70-byte sentences each second
consume 4200 bits/s on a 4800-bit/s port, about 87.5% before other traffic. A bridge
from a fast AIS feed cannot forward everything to that port losslessly. Choose
allowlisted sentences and rates, document loss, measure queue age and drops, and
reserve margin. Do not solve congestion by forwarding old navigation values late.
